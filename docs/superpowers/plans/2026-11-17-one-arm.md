# One arm for the guns (minigun, Remington) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The minigun and the Remington show the grenade launcher's arms, each on its own skeleton and clips.

**Architecture:** An offline tool refits the launcher's arm mesh to a gun's skeleton by anatomy and rewrites the gun's
.glb without its old arm or any arm texture; at load the game gives such an arm the launcher's own colour map.

**Tech Stack:** Python 3 + numpy (run with `uv run --no-project --with numpy python`), C / raylib 6.0, bash tests.

**Spec:** docs/superpowers/specs/2026-11-17-one-arm-design.md

## Global Constraints

- Each gun keeps its skeleton, inverse bind matrices, clips and mesh ORDER (minigun barrel = mesh 1; arms = mesh 6;
  Remington arms = mesh 0). `assets/<gun>.glb.ibm` and `.glb.parts` are not touched.
- Inputs are read from git at commit b75ba60 (`git show b75ba60:assets/<gun>.glb`), never from the working file.
- No game runs side by side (one debug log); automated runs use `CHERNOBYL_BACKGROUND=1`; no synthetic keystrokes.
- Nothing is committed or deployed without the owner asking.

## Review Focus

- A gun whose arm file has no texture but the launcher failed to load: the arm must still draw (plain), not vanish.
- The reload and fire clips, not only the idle pose: hands on the gun, no open sleeve end on screen.
- The browser / phone pack (tools/web/pack_web.py shrink_glb) on a .glb with fewer images.
- The LMG / AK spare slots and the claymore's own sleeve (MineSleeve) still resolve after LoadWeapon changes.
- A second run of the tool gives byte-identical files.

  primitive keeps its mesh index; its material is named `arms` and has no texture; POSITION count equals the
  launcher arm's (7436) plus the sleeve extension's vertices; no accessor, bufferView or image is left unreferenced.

  has no unreferenced bufferView; a second tool run leaves both files byte-identical.

- [ ] **Step 3: Implement `tools/arms/refit_arms.py`**: roles per rig (`maesen`: L/R_arm, _elbow, _wrist, thumb/point/
